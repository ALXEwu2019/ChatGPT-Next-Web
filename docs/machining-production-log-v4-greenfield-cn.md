# 机加工车间生产日志管理系统 — 全新建设方案 v4

> **建设性质：绿场新建（Greenfield）**  
> 不修改、不依赖旧飞书多维表格中的 78+ 列、旧汇总自动化、旧工序编号（#40/#50）及历史公式。  
> 旧系统仅可作为业务参考或只读归档，不作为新系统数据源。

**核心原则：** 批号归生产，追溯号归质量；首道选管控批，下道选上道批；有效数汇总，对账看下发量。

---

## 1. 建设目标与边界

### 1.1 目标

| 目标 | 说明 |
| --- | --- |
| 生产报工 | 三产品、多工序、多区域按行报工，可汇总、可对账 |
| 质量闭环 | 不良 → 返工 → 品保确认 → 有效合格/有效报废 |
| 批次管控 | 已下发批号约束首道；下道只能接上道已产出批号 |
| 产量汇总 | 按工序规则汇总有效产量，**由 API 脚本定时同步，不用飞书公式聚合** |
| 问题追溯 | 完整追溯号独立生成，用于客诉/不良，**不参与生产汇总** |

### 1.2 绿场边界（明确不做）

| 不做 | 原因 |
| --- | --- |
| 修补旧主表横向产量列 | 架构根源问题 |
| 飞书自动化写汇总合计 | 与脚本双写、难维护 |
| 用追溯号选批/汇总 | 业务域混淆 |
| 工序表按产品重复行（#2030-STOPPER） | 配置冗余 |
| 下道手填跨产品/跨道批号 | 防串批 |

### 1.3 技术分工

| 能力 | 实现方式 |
| --- | --- |
| 追溯号、有效数公式 | 飞书公式 + 产品追溯规则表 |
| 选批约束、视图权限 | 飞书视图 + 关联筛选（静态） |
| 批工序汇总 | 飞书开放平台 API + `sync_batch_summary.py` + 服务器 cron |
| 不良/返工状态 | 主表状态字段 + 不良明细表 |
| 超产对账 | 对账视图 +（可选）脚本回写告警 |
| 表结构维护 | OpenClaw / BKD 助理 + 人工验收 |

## 3. 核心概念

### 3.1 批号 vs 追溯号

| | 生产批号 | 完整追溯号 |
| --- | --- | --- |
| 用途 | 计划、选批、传批、汇总、对账 | 质量追溯、不良、客诉 |
| 示例 | `S-260617-A` | `S-260617-A-0624-MG02` |
| 参与汇总 | ✓ | ✗ |
| 下道选批 | ✓ 只选批号 | ✗ |

**关系：** 追溯号结构上含批号，业务上不能替代批号。

### 3.2 产量字段生命周期

| 字段 | 阶段 | 填写人 | 用途 |
| --- | --- | --- | --- |
| 合格数量、报废数量 | 初报 | 操作工 | 原始报工 |
| 返工后合格数、返工后报废数 | 返工后 | 班组长 | 返工结果 |
| 有效合格数量、有效报废数量 | 品保确认后 | 公式/确认 | **汇总与对账唯一来源** |

### 3.3 计入汇总条件（建议默认）

```
工序下发状态 ∈ {已确认, 已审核}
且 有效合格数量、有效报废数量 已非空
```

## 5. 追溯号规则（质量域）

**统一结构：** `生产批号 - 填报月日(MMDD) - 末段标识`

| 工序 | 样例 | 末段来源 | 说明 |
| --- | --- | --- | --- |
| #2030 | S-260617-A-0623-A1 | 生产区域 A1/A2 | 每区每报工日行 |
| #4050 | S-260617-A-0624-MG02 | 生产区域 MG02/MG03 | 末段为 MG 区 |
| #60 | S-260617-A-0625-J1 | 工位 J1/J2 | 仅追溯；汇总不按 J 拆 |
| #70 | 待确认 | 待确认 | 见决策项 B2 |
| #80 | 待确认 | 待确认 | 仅止动块 |

**公式（主表）：**

```text
完整追溯号 = 批号文本 & "-" & 填报月日 & "-" & 末段字段
```

末段字段来源由 **产品追溯规则表** 按 `产品 + 工序代码` 配置，不用工序名称匹配。

## 6. 汇总规则（生产域）

### 6.1 原则

- 数据源：主表 `有效合格数量`、`有效报废数量`
- 同步：`sync_batch_summary.py`（cron），**关闭飞书汇总自动化**
- 汇总键：**不含追溯号、不含月日**（除配置明确要求外）

### 6.2 脚本聚合配置（初始）

```json
{
  "aggregation_by_process": {
    "#4050": ["batch_text", "product", "process_code", "production_area"],
    "#60": ["batch_text", "product", "process_code"]
  },
  "default_aggregation": ["batch_text", "product", "process_code"]
}
```

说明：`product` 用于共用工序时防 STOPPER/止动块误合并（若批号全局唯一可讨论去掉）。

### 6.3 汇总表示例

| 批号文本 | 产品 | 工序 | 生产区域 | 合格合计 | 报废合计 | 批工序键 |
| --- | --- | --- | --- | --- | --- | --- |
| S-260617-A | STOPPER | #4050 | MG02 | 500 | 0 | S-260617-A-#4050-MG02 |
| S-260617-A | STOPPER | #60 | （空） | 350 | 2 | S-260617-A-#60 |

### 6.3 #2030 汇总维度（待拍板 A1）

| 选项 | 汇总键 | 适用场景 |
| --- | --- | --- |
| ① 合并 | 批号 + #2030 | 对账按批+工序总量 |
| ② 拆分 | 批号 + #2030 + 区域(A1/A2) | 按区考核产量 |

### 7.6 对账层（视图/公式）

关联 `入库批次管控` 与 `批工序产量汇总`：

```text
对账差异 = 合格合计 - 本工序下发数量
是否超产 = 对账差异 > 0
```

#4050 无区域下发时：`SUM(同批各区合格) ≤ 批+工序总下发量`。

## 8. 状态机（生产日志主表）

```
待报工 → 已报工
       → 待返工（有不良明细）
       → 待品保确认（返工数已填）
       → 已确认 / 已审核（有效数生效，可计入脚本汇总）
```

| 状态 | 可计入汇总 | 可被选为上道批号池 |
| --- | --- | --- |
| 已报工 | 否（默认） | 待确认 D1 |
| 已确认/已审核 | 是 | 是（且有效合格>0） |

### 9.1 下道选批实现（不用动态「当前记录」筛选）

飞书关联字段若不支持「产品=当前记录」动态筛选，采用：

**方案 1（推荐）：分产品视图 + 静态筛选**

- 止动块·#4050 视图：`上道批号` 关联筛选 `产品=止动块` + `上道工序=#2030` + `状态已确认`

**方案 2：上道批号池辅助表**

脚本或公式定时生成「可选批号」列表，主表关联该表。

**方案 3：批号文本只读 + 自动化**

选上道生产记录后自动带出批号，禁止手改。
