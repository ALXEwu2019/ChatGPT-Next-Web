# 不良原因联动规则表导入（飞书 AI Prompt）

> **重要：** 用户粘贴的 137 行是 **产品×工序×原因×处置** 联动规则，**不能**整表写入「不良原因库」。  
> 正确做法：**两层分离** — 原因库放词典，联动规则表放筛选配置。

---

## 一、为什么要分两张表？

| 层级 | 表名 | 存什么 | 行数 |
| --- | --- | --- | --- |
| L0 词典 | **不良原因库** | 原因名称（全局唯一） | **46 行** |
| L0 配置 | **不良原因联动规则表** | 产品 + 工序 + 原因 + 默认处置 | **137 行** |

**不能把 137 行塞进原因库的原因：**

1. 同一原因名会重复几十次（如「倒角」出现 10+ 次）。
2. **同一产品+工序+原因，既有返工行又有报废行**（共 20 组），例如 STOPPER·#2030·总高 同时有返工和报废。
3. 因此 **处置类型（返工/报废）必须写在联动规则表**，不能写在原因库主数据上。

---

## 二、不良原因库（46 条，无处置类型）

### 推荐字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 原因代码 | 文本 | = 原因名称 |
| 原因名称 | 文本 | 全局唯一 |
| 原因类别 | 单选 | 尺寸 / 外观 / 工艺 / 其他（可选） |
| 启用状态 | 单选 | 启用 / 停用 |

**不要**在原因库放「处置类型」字段（会与联动规则冲突）。

## 三、不良原因联动规则表（137 条）

### 推荐字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 规则名称 | 公式/文本 | `产品 & "-" & 工序代码 & "-" & 原因名称 & "-" & 默认处置` |
| 产品 | 关联→产品表 | STOPPER / 止动块 / PTJ92 |
| 工序代码 | 关联→工序表 | **只用** `#2030`、`#4050`…，不用带产品后缀名 |
| 不良原因 | 关联→不良原因库 | 选上表 46 条之一 |
| 默认处置类型 | 单选 | 返工 / 报废 |
| 启用状态 | 单选 | 启用 / 停用 |

**唯一键：** 产品 + 工序代码 + 不良原因 + 默认处置类型  
（同一原因在同一工序下可同时有「返工」和「报废」两行，这是旧系统真实逻辑，必须保留。）

### 旧列 → 新列映射

| 你粘贴的列 | 联动规则表 |
| --- | --- |
| 第 1 列 返工/报废 | 默认处置类型 |
| 第 2 列 产品 | 产品（关联） |
| 第 3 列 #2030车床自动化-STOPPER | **丢弃**，改用第 4 列 |
| 第 4 列 #2030 | 工序代码（关联工序表） |
| 第 5 列 倒角… | 不良原因（关联原因库） |
| 第 6 列 启用 | 启用状态 |

### 各产品×工序规则数量

| 产品 | 工序 | 规则数 | v4 是否在用 |
| --- | --- | ---: | --- |
| STOPPER | #2030 | 27 | ✓ 首道 |
| STOPPER | #4050 | 1 | ✓ |
| STOPPER | #60 | 14 | ✓ |
| 止动块 | #2030 | 27 | ⚠ 旧链残留，v4 首道为 #4050 |
| 止动块 | #4050 | 1 | ✓ 首道 |
| 止动块 | #60 | 14 | ✓ |
| PTJ92 | #1020 | 29 | P2 后 |
| PTJ92 | #3040 | 17 | P2 后 |
| PTJ92 | #50 | 7 | P2 后 |

**止动块·#2030 共 27 条：** 建议 **导入但启用状态=停用**，或单独视图「历史·止动块#2030」备查；v4 报工视图不要引用。

### 填报时如何用（不良明细表）

1. 从关联生产记录带出 **产品、工序代码**。
2. 不良原因下拉 = 联动规则表中 `产品+工序+启用` 匹配的记录。
3. **先选「返工 / 报废」**（或在两个分视图里填），再筛原因 — 避免「总高」等同名原因歧义。
4. 选中原因后，**默认处置类型** 自动写入不良明细的处置字段（可人工改）。

## 四、飞书 AI Prompt（联动规则 137 行）

---BEGIN---

请在「机加工生产日志 v4」配置 **不良原因联动规则表**（若表不存在则新建，不要重建应用）。

## 前置

1. **不良原因库** 已录入 46 个唯一原因名（见 `docs/openclaw-defect-reason-import-prompt-cn.md`，但原因库 **不含处置类型**）。
2. **工序表** 使用通用代码 `#2030`、`#4050`、`#60`、`#70`、`#80`、`#1020`、`#3040`、`#50`。
3. **产品表** 已有 STOPPER、止动块(ZHIDONG)、PTJ92。

## 联动规则表字段

规则名称（公式）、产品（关联产品表）、工序代码（关联工序表）、不良原因（关联不良原因库）、默认处置类型（单选：返工/报废）、启用状态（启用/停用）。

## 导入规则

1. 共 **137 行**，列顺序：默认处置类型、产品、（忽略工序长名称）、工序代码、不良原因名、启用状态。
2. 工序代码、产品、不良原因 **必须用关联字段** 选记录，禁止手打 `#2030车床自动化-STOPPER`。
3. 同一产品+工序+原因 若既有返工又有报废，保留 **两行**（共 20 组双行，属正常）。
4. **止动块 + #2030** 的 27 行：导入后 **启用状态改为停用**（v4 止动块首道为 #4050）；或整组不导入由你判断并说明。
5. 不要改生产日志主表、汇总脚本、不良明细表结构（除非缺关联字段）。

## 完成后回报

1. 联动规则表总行数（目标 137，或 110 若停用止动块#2030）
2. 按产品×工序统计行数是否与上表一致
3. 抽 3 行截图：产品、工序代码、不良原因、默认处置类型
4. 确认不存在手打带 `-STOPPER` 后缀的工序

**禁止：** 把 137 行写入不良原因库；重建应用。
