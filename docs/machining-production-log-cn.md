# 机加工车间生产日志管理系统整体架构方案 v3.0

2026 年 6 月 · 飞书多维表格 · 重构版

## 已定稿决策

- A2：主表作库 + 多视图。
- PTJ92：启用检测批次表。
- C2 Phase1：同步报工产量行模型。
- 工序「已下发」= 报工完成 + 追溯号已生成 +（可选）审核通过。
- #40 区域码启用 MG2 / MG3 / MG4。

使用说明：本文作为飞书多维表格搭建、评审和后续批注的主方案。标注【待填】处需要业务继续补充。

## 第一部分 架构愿景

### 1.1 为什么要重构而不是修补

| 现状问题 | 重构方向 |
| --- | --- |
| 主表 78+ 列，按产品 x 区域横向堆列 | 报工头 + 产量明细行模型 |
| 追溯工作流反复失败、与公式打架 | 公式管拼接，工作流管状态 |
| 新产品 = 加几十列 + 复制工作流 | 产品追溯规则表配置驱动 |
| 总表操作易跳工序、易填错 | 工序专用视图 + 上道记录强制关联 |

### 1.2 五层架构

| 层级 | 职责 | 核心表 |
| --- | --- | --- |
| L1 计划层 | 批号下发、进度、结案 | 入库批次管控表 |
| L2 报工层 | 工序头、追溯号、工序状态 | 生产日志主表（瘦身） |
| L3 产量层 | 区域 x 类型 x 数量 | 报工产量明细表（新建） |
| L4 质量层 | 不良、返工、检测合并 | 不良明细、返工清单、检测批次 |
| L5 仓储层 | 出入库 | 仓库出入库表 |

检测批次表：STOPPER、止动块、PTJ92 三产品均启用。

架构总纲：主表做头、明细做量、配置做规则、视图做入口、工序链不可跳、批号管终点。

## 第二部分 目标数据模型

### 2.1 生产日志主表（报工头表 · 瘦身后）

每条记录 = 一道工序的一次报工。不再包含 `A1合格数量-STOPPER#2030` 等产量列。

| 字段组 | 字段 | 说明 |
| --- | --- | --- |
| 关联 | 生产批号、产品、工序、操作工、班次 | 基础关联 |
| 镜像 | 批号文本、填报月日、生产区域文本、工序代码 | 供公式/工作流 |
| 工序链 | 上道生产记录、工序下发状态、是否可供下道选用 | 防跳工序 |
| 追溯 | 追溯根号、完整追溯号、上道追溯根号、检测批次号 | 公式 + 工作流 |
| 批号合并 | 合并批号、合并批号文本 | #50 后自动带出可改 |
| 审核 | 审核状态、审核人、审核意见 | 可选纳入已下发 |
| 校验 | 数量校验、是否异常 | 聚合明细表 |

### 2.2 报工产量明细表（新建 · 行模型 C2）

| 字段 | 说明 |
| --- | --- |
| 关联报工头 | 关联到生产日志主表 |
| 生产区域 | A1 / B1 / MG2 等 |
| 报工类型 | 合格 / 返工 / 报废 |
| 数量 | 整数 |

返工回写改为按“关联报工头 + 区域 + 类型”累加，不再写 `A1返工完成` 固定列。

### 2.3 产品追溯规则表（新建 · 配置驱动）

新产品只增配置行，不增主表列。建议字段：

| 字段 | 说明 |
| --- | --- |
| 产品 | STOPPER / 止动块 / PTJ92 / 后续新品 |
| 追溯起点工序 | 根号开始生成的工序 |
| 根号模板 | 如 批号-月日-区域 |
| 中间段模板 | 如 上道根号-MG区 |
| 检测批模板 | 如 上道根号-J流水 |
| 是否用检测批次表 | 是/否 |
| 是否合并批号 | 是/否 |
| 出库工序 | 对应终道或出库动作所在工序 |

### 2.4 原产量列处理

| 阶段 | 处理 |
| --- | --- |
| 迁移期 | 历史数据导入明细表；原列只读保留 |
| 试运行 | 新报工只录明细表；原列隐藏 |
| 稳定后 | 原列归档/删除 |

## 第三部分 工序链与下发管控

### 3.1 「已下发」定义（已确认）

| 条件 | 说明 |
| --- | --- |
| 报工完成 | 必填项已保存 |
| 追溯号已生成 | 该工序要求的号非空 |
| 审核通过（可选） | 若启用审核，审核状态 = 已通过 |

公式：`是否可供下道选用 = 报工完成 AND 追溯号已生成 AND 可选审核条件满足`。

### 3.2 工序不可跳

| 产品 | 工序 | 选择来源 |
| --- | --- | --- |
| STOPPER | #2030 | 入库批次管控表（批号 >= 已下发） |
| STOPPER | #40 | 上道生产记录（#2030 已下发） |
| STOPPER | #50 | 上道生产记录（#40 已下发） |
| STOPPER | #60 | 合并批号（#50 已完成） |
| 止动块 | #40 -> #50 -> #60/#70 | 同上逻辑，追溯从 #40 起 |
| PTJ92 | #1020 -> #3040 -> #50 | 上道 #3040 已下发；检测批次表；同记录出库 |

### 3.3 上道生产记录（关键实现）

- 类型：关联到生产日志主表（单选）。
- 筛选：前道工序 + 是否可供下道选用 = 是 + 同生产批号。
- 上道追溯号：查找引用自动带出。

## 第四部分 三产品追溯编码

### STOPPER

| 工序 | 规则 | 示例 |
| --- | --- | --- |
| #2030 | 追溯根号 = 批-月日-区域 | S-260616-A-0616-A1 |
| #40 | 完整号 = 上道根号-MG区 | S-260616-A-0616-A1-MG2 |
| #50 | 检测批 = 上道-MG区-J | ...-MG2-J01 |
| #50 完成 | 合并批号（自动 = 批号，可改） | S-260616-A |
| #60 | 合并批号 | S-260616-A |

### 止动块

| 工序 | 示例 |
| --- | --- |
| #40 根号 | S-260616-A-0616-B1 |
| #50 检测批 | ...-B1-J01 |
| 合并批号 / #60 / #70 | S-260616-A |

### PTJ92（启用检测批次表 · D2：#50 检测 + 出库合一）

| 工序 | 规则 | 示例 |
| --- | --- | --- |
| #1020 / #3040 | 追溯根号 = 批-月日 | S-260616-A-0616 |
| #50 | 同一报工记录完成：检测纳入（J号）+ 合并批号 + 出库 | 见下 |
| #50 · 检测批 | 检测批 = 上道根号-J流水；写入检测批次表/明细 | S-260616-A-0616-J01 |
| #50 · 合并批号 | 自动 = 生产批号，可改 | S-260616-A |
| #50 · 出库 | 同记录按合并批号记出库数量 | S-260616-A |

定稿：PTJ92 无单独 #60 出库工序；#50 为终道工序。

## 第五部分 视图架构（A2）

主表 = 数据库。【总表】= 审计/导出。日常操作只用工序/职务视图。

| 视图 | 使用人 | 要点 |
| --- | --- | --- |
| 计划-批号看板 | 计划 | 下发、进度、结案 |
| STOPPER-#2030 报工 | 车床工 | 选批号、录产量明细 |
| STOPPER-#40 报工 | 磨床工 | 选上道 #2030 记录、MG2/3/4 |
| STOPPER-#50 检测 | 品保 | 检测批、合并批号 |
| STOPPER-#60 出库 | 仓储 | 合并批号 |
| 止动块各工序视图 | 对应人员 | 同上逻辑 |
| PTJ92-#50 检测出库 | 品保/仓储 | 上道 #3040、检测批、合并批号、出库数量（同记录） |
| 异常预警 | 班长/品保 | 数量/追溯异常 |
| 【总表】生产日志 | 管理员 | 全量只读/导出 |

## 飞书 AI 协作建议

后续可使用内置面具“机加工生产日志助手”继续处理：

- 把业务补充内容转换为字段清单、视图筛选条件和公式说明。
- 校验新字段是否违背“主表做头、明细做量”的总纲。
- 按 STOPPER、止动块、PTJ92 分别生成飞书多维表格配置步骤。

## 飞书 AI 对话核对流程

当飞书文档或多维表格里已经做了修改时，不直接接受修改稿，也不直接否定修改稿。先用飞书 AI 按以下对话流程核对，再把结论回写到方案。

### 第 1 轮：让飞书 AI 提取修改点

复制修改后的方案或表结构给飞书 AI，并提问：

```text
请只基于我提供的内容，提取相对 v3.0 基线发生变化的地方。
按以下维度输出：
1. 表结构变化
2. 字段变化
3. 公式变化
4. 工作流变化
5. 视图/权限变化
6. 工序链变化
7. 追溯编码变化
8. 出入库逻辑变化
不要评价对错，只列出变化点和所在位置。
```

### 第 2 轮：让飞书 AI 对照 v3.0 总纲查冲突

```text
请把上一步变化点逐条对照以下 v3.0 总纲：
- 主表做头
- 明细做量
- 配置做规则
- 视图做入口
- 工序链不可跳
- 批号管终点
- 公式管拼接，工作流管状态

请输出：
| 修改点 | 是否冲突 | 冲突原因 | 建议保留/调整/取消 |
如果没有冲突，也要说明为什么可以落地。
```

### 第 3 轮：让飞书 AI 模拟三产品流程

```text
请用修改后的方案，分别模拟以下三条完整流程：
1. STOPPER：#2030 -> #40 -> #50 -> #60
2. 止动块：#40 -> #50 -> #60/#70
3. PTJ92：#1020 -> #3040 -> #50检测出库

每个流程都要说明：
- 当前工序从哪里选上道记录
- 追溯号/检测批/合并批号由哪个字段生成
- 产量写入主表还是明细表
- 什么时候算已下发
- 下一道为什么不能跳选
- 出库准入条件是什么
最后列出跑不通或需要人工补规则的地方。
```

### 第 4 轮：让飞书 AI 做落地性评审

```text
请站在飞书多维表格实际搭建角度评审修改后的方案。
重点判断：
1. 关联字段是否能按同批号、前道工序、已下发状态筛选
2. 公式字段是否依赖了工作流异步结果
3. 工作流是否在改写公式字段或造成循环触发
4. 明细表聚合是否能支持数量平衡
5. 视图入口是否能避免工人进入总表误填
6. PTJ92 #50 检测+出库合一是否能在同一记录闭环
7. 历史数据迁移是否会污染新行模型

请输出：
| 风险 | 严重级别 | 是否阻碍上线 | 修正方案 |
```

### 第 5 轮：形成可执行改稿

```text
请把最终可落地版本输出为三张表：
1. 必须保留的修改
2. 必须调整的修改
3. 暂缓或取消的修改

每一行包含：修改内容、原因、涉及表、涉及字段/视图/工作流、落地动作。
```

### 判定标准

修改后的方案只有同时满足以下条件，才视为可以落地：

- 不把区域、产品、工序产量重新横向堆回主表。
- 任一后道工序都必须能通过“上道生产记录”关联到已下发前道记录。
- 追溯号、检测批、合并批号的生成职责清楚，不由多个工作流反复覆盖。
- 报工产量明细表可以按报工头、区域、类型聚合校验。
- PTJ92 #50 可以在同一报工记录中完成检测批、合并批号和出库，不新增单独 #60。
- 日常用户只从工序/职务视图进入，不依赖总表人工筛选。
- 【待填】事项没有被飞书 AI 编造，必须由业务确认后写入。
