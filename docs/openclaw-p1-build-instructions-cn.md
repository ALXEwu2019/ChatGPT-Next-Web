## 3. 主表关联与自动化（P1）

| 视图 | 字段 | 关联目标 | 筛选 |
| --- | --- | --- | --- |

| 止动块·#4050 报工 | 关联管控批 | 入库批次管控表 | 产品=ZHIDONG，工序=#4050，状态=已下发 |

```text

```


### 3.3 是否异常（超产预警，公式）

P1 可在主表增加查找汇总表的对账公式（或仅在对账视图展示）：

```text
是否异常 = 本行有效合格数量 > 0 AND 对账差异 > 0
```

对账差异在「对账视图」中计算（见 §4）。

## 4. 对账视图

### 4.1 视图：管理·批工序对账

新建视图或独立对账表（推荐：**管控表扩展视图** 或 **汇总表关联管控**）。

**关联逻辑：**

```
入库批次管控.批号文本 + 产品 + 工序代码 [+ 生产区域]
  ←→ 批工序产量汇总.批号文本 + 产品 + 工序代码 [+ 生产区域]
```

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| 批号文本 | 管控 / 汇总 | |
| 产品 | 管控 | |
| 工序代码 | 管控 | |
| 本工序下发数量 | 管控 | |
| 合格合计 | 汇总（查找） | 脚本写入 |
| 对账差异 | 公式 | `合格合计 - 本工序下发数量` |
| 是否超产 | 公式 | `对账差异 > 0` |

### 4.2 #4050 对账规则（A3 待选，P1 默认）

**默认方案（批+工序总量）：** 同批同工序多 MG 行在汇总侧按 MG 拆分，管控侧若按 MG 分行则逐行对账；若管控仅批+工序一行，则 `SUM(各区合格合计) ≤ 下发总量`。

| 管控粒度 | 对账方式 |
| --- | --- |
| 按 MG 分行 | 逐行：汇总(MG) vs 管控(MG) |
| 仅批+工序 | 汇总 SUM(MG) vs 管控总量 |

P1 验收前与计划岗确认一种；文档默认 **按 MG 分行对账**（与汇总键一致）。

## 7. P1 端到端验收场景

### 场景 A：STOPPER 首道 → 磨床

1. 管控表下发 `S-260617-A` STOPPER #2030 数量 1000
2. #2030 报工 A1 合格 300、A2 合格 200，均设 **已确认**
3. 脚本 dry-run：`S-260617-A-#2030-A` 合格合计 500
4. #4050 上道批号池可见 `S-260617-A`（不区分 A1/A2）
5. #4050 MG02 报工合格 400，已确认
6. 汇总：`S-260617-A-#4050-MG02` 合格 400
7. 对账：#2030 下发 1000 vs 汇总 A区500+B区(若有) — 未超产

### 场景 B：止动块双 MG 对账

1. 管控 `S-260618-A` #4050 MG02=500、MG03=500
2. 各 MG 报工并确认
3. 对账视图两行均无超产

### 场景 C：批号池排除

1. #2030 报工有效合格=0 → 下道 **不可选**
2. 状态=已报工未确认 → 下道 **不可选**
